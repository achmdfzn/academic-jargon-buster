# Changelog

## 1.27.1 — 2026-11-13

- Dictionary grows 52 → 72 terms: 9 research-methods terms (data saturation, case study, phenomenology, focus group discussion, uji validitas, uji reliabilitas, plus their Indonesian aliases) and 11 statistics terms (t-test, anova, chi-square test, coefficient of determination, uji normalitas, uji homogenitas, descriptive statistics, plus aliases), each with a verified real source — Glaser & Strauss 1967, Yin 2018, Moustakas 1994, Krueger & Casey 2014, Creswell & Creswell 2018, Field 2018, Ghozali 2018 (Cronbach 1951 is cited in the uji reliabilitas explanation). Longest-first matching still wins ("uji validitas" claims its span, "validitas" alone is not double-flagged). Deliberately NOT added: "uji t" (the substring matcher would also match it inside "uji terhadap", a false positive on ordinary Indonesian prose — same precedent as "variance" inside "covariance") and "sample"/"sampel" ("for example" contains "sample", so nearly every academic text would false-positive). 3 new tests; full suite 493/493. `JARGON_VERSION` 1.0.5 → 1.0.6.
- Readability bands: researched, not rescaled. No published source gives Flesch bands calibrated for Indonesian — the only real Indonesian calibration found (Herpindo et al. 2026, *Jurnal Sosioteknologi* 25(2), DOI 10.5614/sostek.itbj.2026.25.2.8; regression on 27,274 sentences from Indonesian undergraduate abstracts) supplies formula coefficients only, no bands, and its authors state no psychometrically validated Indonesian standard exists. The standard Flesch bands stay, with the honesty note. Showing the Herpindo 2026 score as a second, explicitly experimental metric (number only, no band) remains a possible later design decision, not part of this release.

## 1.27.0 — 2026-11-13

- New tool: Readability, the Flesch Reading Ease + Flesch-Kincaid Grade Level for a text (Flesch 1948, J. Appl. Psychol. 32(3), 221–233) — pure formulas on word/sentence/syllable counts, no language model, no API, no minimum word count. RE = 206.835 − 1.015 × (words/sentence) − 84.6 × (syllables/word), clamped to 0–100; FKGL = 0.39 × (words/sentence) + 11.8 × (syllables/word) − 15.59, clamped to a minimum of 0; both rounded to 1 decimal, with the standard Flesch bands (90+ Very easy, 80+ Easy, 70+ Fairly easy, 60+ Standard, 50+ Fairly difficult, 30+ Difficult, below 30 Very difficult). Syllables are counted by EYD rules (vowels a/e/i/o/u; diphthongs ai/au/oi only — "ei" is not one, so "survei" counts 3 and "keindahan" 4; a word with no vowel counts 1). `analyze` always computes it and shows it in the report, the `--json` output, and the web UI (new Readability card in the Analisis Kualitas tab, under the score gauge) — but it never changes the 0–100 score, the four score parts, or the exit code. New subcommand `readability <file|--text> [--lang id|en] [--json]` (informative: exit 0 always, except bad input) and thin shim `readability.py`; no new menu option. Every result carries the honesty note: the Flesch formulas were calibrated for English, so on Indonesian text the score is an indication, not a verdict — Indonesian academic prose usually lands lower because Indonesian words average more syllables, and that is expected, not a bug. Calibration (measured, not claimed): a stiff academic paragraph ("Penelitian ini menggunakan metode survei. Data dikumpulkan melalui kuesioner.") scores RE 0.0, FKGL 28.1 — "Sangat sulit"; a humanized version of the same content ("Saya memakai survei untuk penelitian ini. Saya sebarkan kuesioner untuk mengumpulkan data.") scores RE 0.0, FKGL 21.2 — still "Sangat sulit"; a casual narrative paragraph (96 words, the HUMAN_1 calibration text) scores RE 12.7, FKGL 14.1 — still "Sangat sulit". So on Indonesian text the standard Flesch bands compress at the bottom — even casual prose lands "Sangat sulit" — and the FKGL is what still separates texts (28.1 stiff, 21.2 humanized, 14.1 casual). 30 new tests; full suite 490/490. `READABILITY_VERSION` 1.0.0; `QUALITY_VERSION` 1.2.11 → 1.2.12; `CLI_VERSION` 1.17.1 → 1.18.0.

## 1.26.1 — 2026-11-12

- Audit fixes (third full audit, v1.26.0): the detector verdict can no longer be bought by two signals alone. "Kemungkinan besar AI" / "Likely AI" now needs a score of 60 or more AND at least 3 of the 4 signals applicable — a short text (under 100 words, under 6 sentences) has only burstiness and template phrases, and stiff human prose trips both: a typical methods paragraph scores 80.5 yet is capped to "Campuran / tidak pasti", and a light-AI text scores 83.5 and is capped the same way. The `ai_score` itself is not changed (it stays the honest number); the result carries `verdict_capped` and a `verdict_capped_reason` ("hanya 2 dari 4 sinyal yang berlaku — …"), shown by the CLI and the web UI. The AI band is now ≥ 60 (was ≥ 70), so all three calibration AI texts (78.9 / 66.8 / 65.8, all 4 signals applicable) reach "Kemungkinan besar AI". The 1.26.0 release notes claimed ~27 and ~50 for the methods paragraph and the light-AI text; both numbers were wrong — written before the signal-applicability fix and never re-measured — and are corrected in place above. The self-match hash is one canonical form now (`text.strip()[:100_000]`, one helper): a run over 100,000 characters recognises itself again, and runs saved with the old v1.25.2 hash are still recognised. `serve --host ::1` works over IPv6 (and on a machine without IPv6 it exits 1 with "IPv6 tidak didukung di mesin ini" instead of a `socket.gaierror` traceback). RIS/BibTeX export normalises a lone author string to one author and rejects a non-list `authors` (or a list holding a non-string) with a plain `ValueError`; `save_analysis` and `import_references` validate reference shape before writing. `_split_sentences` protects abbreviations (`Dr.`, `Prof.`, `Drs.`, `dkk.`, `dst.`, `dll.`, `e.g.`, `No.`) and lets a closing quote follow `.`/`!`/`?`. A DOI is `missing` when a checked source returns 404 and no source errors — a Crossref 404 is already `missing` when OpenAlex was merely skipped for lack of a key; only a source error, or nothing checked at all, leaves it `unverified`. The ai-detector skill table now says lexical diversity applies at 100+ words and starter repetition at 6+ sentences. Multipart boundaries are read quote-aware, so `boundary="a;b"` parses; the stdlib 501 page for PUT/DELETE/OPTIONS/HEAD carries the same CSP/nosniff/DENY headers as every other response (and no longer hangs for lack of a Content-Length); a client aborting mid-request is swallowed quietly instead of logging a traceback; every connection gets a 30-second socket timeout so a stalled client cannot hold one of the 8 handler slots forever (verified end to end: 8 stalled connections block a 9th request until one closes). BibTeX escapes volume, issue, and year, sanitises keys (braces, commas, whitespace become `-`), and normalises en/em dashes in page ranges to `--` like RIS. The three remaining library read paths (`get_analysis`, `list_references`, `export_references`) no longer create the database file when it does not exist. 34 new tests; full suite 460/460. `DETECTOR_VERSION` 1.0.0 → 1.0.1; `CITATION_VERSION` 1.5.2 → 1.5.3; `QUALITY_VERSION` 1.2.10 → 1.2.11; `CLI_VERSION` 1.17.0 → 1.17.1.

## 1.26.0 — 2026-11-12

- New tool: AI Detector, a heuristic check whether a text reads like AI writing — pure stdlib, no language model and no API. `detect_ai()` scores four signals 0–100 (burstiness, weight 30: coefficient of variation of sentence lengths, 100 at CV 0 and 0 at CV 0.55; template phrases, weight 30: density of a curated original list of 20 Indonesian + 10 English transition phrases per 100 words, 100 at 5 per 100; lexical diversity, weight 20: type-token ratio, 100 at TTR 0.42 and 0 at 0.72; starter repetition, weight 20: share of sentences sharing the modal opening two words, 100 at a 0.50 share and 0 at 0.20) and takes the weighted mean of the applicable signals only. Verdict bands: ≥ 70 likely AI, 40–69 mixed / uncertain, < 40 likely human; under 30 words the verdict is "too short" with `ai_score` None, and an empty text is the plain `teks kosong` error. Every sentence is scored too (most AI-like first: 60% template phrase, 30% closeness to the mean sentence length, 10% modal starter). The honesty note is always attached: the score is an indication, never proof — human text can be flagged and AI text can pass, so it must never be used to accuse anyone. Calibration: 6 original texts in `tests/test_detector.py` (3 human-like, 3 AI-like, written from scratch) — human-like score 0.0, AI-like 78.9 / 66.8 / 65.8, and a typical human methods paragraph scores 80.5 while a light-AI text scores 83.5 — both capped to "Campuran / tidak pasti" in v1.26.1 because only 2 of 4 signals apply to such short texts. (The 1.26.0 release notes claimed ~27 and ~50 for these two texts; both numbers were wrong — written before the signal-applicability fix and never re-measured.) New subcommand `detect <file|--text> [--lang id|en] [--json]` (informative: exit 0 always, except bad input) and menu option 7, Deteksi AI (language switch moves to 8). New web UI tab (sixth) with the same SVG gauge (band colors reversed: a high AI score is red), the four signal components, sentences scoring 70+, and the note always visible; new endpoint `POST /api/detect` (1 MB body cap, honest 400). New skill `ai-detector` v1.0.0 and thin shim `ai_detector.py`. 41 new tests; full suite 426/426. `DETECTOR_VERSION` 1.0.0; `CLI_VERSION` 1.16.2 → 1.17.0.

Citations are now proportional — 25 × (cited − missing) / cited — so every cited marker missing scores 0 instead of a half-credit 12.5; a DOI that could not be checked (`unverified`) earns half credit (12.5) instead of none. ## 1.19.0 — 2026-11-12

- New internal duplication check: `duplicates naskah.txt` (or `--text "..."`) compares every sentence of at least 6 words against every sentence of the user's own saved runs in the library, plus against the other sentences of the text itself. A match is a normalized difflib similarity of 0.8 or more (`--threshold` changes it, 0–1); only the best match per sentence is reported, with the source run (id, title, date) or "naskah ini" for a repeat inside the text. The text itself is never matched against its own saved copy (same SHA-256 hash), so re-analyzing a saved run does not flag every sentence. A word-overlap pre-filter (half the words of the shorter sentence shared) keeps the comparison fast. `analyze --duplicates` runs the same check in the quality pass (the result gains a `duplicates` key and the report a Duplikasi section); duplicates never change the score and never change the exit code — they are a warning to read, not a failure. `duplicates` itself exits 1 when it finds any, 0 when clean. Also in the interactive menu (Pustaka, option 6) and as a "Cek duplikasi dengan pustaka" checkbox on the Analisis Kualitas tab of the web UI, with a Duplikasi card in the result. `CLI_VERSION` 1.11.0 → 1.12.0; `QUALITY_VERSION` 1.2.1 → 1.2.2 (the quality-check skill documents the check).
